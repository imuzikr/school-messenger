띵동 학교 메신저 0.2.135

Windows 10/11 x64용입니다. ZIP은 폴더 전체를 풀어서 사용하세요.
START-CLIENT.cmd: 실제 클라이언트 (관리자가 제공한 서버 연결 파일 필요)
START-SERVER.cmd: 교내 서버 설정과 관리
START-DEMO.cmd: 실제 전송 없는 화면 체험
개발 폴더의 Dingdong.exe는 기본적으로 화면 체험 모드입니다.
별도 클라이언트/서버 배포 ZIP의 Dingdong.exe는 해당 역할로 바로 실행됩니다.
사용 PC에 Node.js를 설치할 필요는 없습니다. 코드 서명은 적용하지 않았습니다.

추가 기능: 메시지함의 회신·제출 현황, 통합 검색(Ctrl+K).
자세한 사용법: resources/app/WORK-TOOLS.md
업데이트 후 트레이에서 띵동 종료를 선택하고 다시 실행하세요.

0.2.135 학교 테스트용 업데이트
- 공유 일정을 받거나 메일을 회수할 때, 같은 ID를 쓰는 다른 사람의 기존 일정을 보호합니다.
- 같은 주소에서 여러 로그인을 동시에 시도할 때도 시도 횟수와 동시 검사 수를 제한합니다.
- 서버 응답이 나뉘어 도착해도 교직원 이름과 일정 제목의 한글이 올바르게 표시됩니다.
- 서버가 일시적으로 오류를 반환하거나 실시간 연결의 응답이 멎으면 클라이언트가 다시 연결을 시도합니다.

0.2.134 예약 발송과 서버 정리
- 예약 시각에 접속 중인 수신자의 메시지함이 자동으로 갱신됩니다. 서버가 꺼져 있던 사이에 시각이 지난 예약은 서버를 다시 켜면 발송됩니다. 예약 첨부파일의 10일 보관은 실제 발송 시점부터 시작합니다.
- 서버는 만료된 첨부파일과 로그인 세션을 1분마다 별도로 정리합니다. 보관 기간이 끝난 파일은 즉시 다운로드가 차단되고, 만료된 세션으로는 요청할 수 없습니다.

0.2.133 첨부파일과 서버 여유 공간
- 서버는 파일당 500 MB, 메시지당 합계 2 GB, 발송 후 10일 보관을 유지합니다. 새 첨부를 받을 때는 전송 중인 파일에서 아직 받지 않은 용량을 계산하고 메시지와 수신 확인 기록용으로 2 GB를 남깁니다.
- 서버 관리 창에서 새 첨부에 쓸 수 있는 공간과 전송 중인 파일의 예약 용량을 확인할 수 있습니다.
- 공간이 부족하면 발신자의 보낸 메시지함에 실패 사유가 표시됩니다. 서버 공간을 확보한 후 해당 메시지에서 ‘다시 보내기’를 누르세요. 첨부를 다시 선택할 필요가 없습니다.

0.2.132 기존 PC와 보관 파일을 모두 잃었을 때
- 보관 파일이 있으면 로그인 화면에서 ‘기존 PC 보관 파일 가져오기’를 사용하세요.
- 보관 파일도 없으면 새 PC에서 기존 계정으로 로그인을 시도한 뒤 ‘새 PC 보안 키 복구 요청’을 누릅니다. 안내를 확인하고 요청 코드를 받아 관리자에게 직접 전달하세요.
- 관리자는 서버 PC의 ‘교직원 계정 관리’에서 이름과 아이디를 확인하고 ‘보안 키 복구’를 누릅니다. 신청자 본인을 확인한 후 15분 안에 요청 코드와 관리자 비밀번호를 입력해 승인하세요. 관리자 본인의 PC를 잃은 경우에도 서버 관리 창에서 같은 절차를 따릅니다.
- 새 PC에서 다시 로그인한 후 ‘설정 → 내 메시지 보관·보안’의 내 보안 번호를 동료에게 직접 알려 주세요. 동료가 같은 화면에서 새 번호를 대조하면 송수신을 재개할 수 있습니다. 서버와 교직원 클라이언트를 함께 업데이트하세요.
- 이전 PC와 보관 파일에 있던 기록은 새 PC에서 복구할 수 없습니다. 이전 키로 미수신한 메시지, 이전 키로 보낸 메시지·예약 발송의 남은 전달은 취소되므로 필요하면 재발송을 요청하세요. 다른 교사가 보낸 단체 메시지는 나머지 수신자에게 계속 전달됩니다.

0.2.131 메시지 전송 확인과 예약 도착
- 서버와 클라이언트를 함께 업데이트하세요. 다른 PC에서 같은 발송 순번을 썼을 때 해당 메시지의 접수가 증명되지 않으면 보낸함에 ‘발송 여부 확인 필요’로 표시합니다. 수신자에게 확인한 뒤 필요할 때만 새로 작성하세요.
- 접속 중인 수신자의 메시지함은 예약 시각에 자동 갱신됩니다.

0.2.130 교직원 PC 자동 로그인
- 서버와 클라이언트를 함께 업데이트하세요. 로그인 화면에서 ‘이 PC에서 자동 로그인’을 선택하면 다음 Windows 로그인 때 띵동이 같은 계정으로 열립니다. 임시 비밀번호는 먼저 변경하세요.
- 자동 로그인 정보는 현재 Windows 사용자 계정으로 보호되며, 비밀번호와 별개입니다. 개인 보관 파일로 내보낼 때는 제외됩니다.
- 로그아웃하면 이 PC의 자동 로그인이 해제됩니다. 관리자가 비밀번호를 초기화하거나 약 90일 동안 서버를 사용하지 않은 경우 다시 로그인하세요.

0.2.129 바탕화면 바로 가기
- 교직원용 클라이언트를 처음 실행하면 현재 Windows 사용자의 바탕화면에 ‘띵동 메신저’ 바로 가기를 만듭니다. 이전 버전에서 업데이트한 경우에도 적용됩니다.
- 프로그램을 옮긴 뒤에는 새 위치에서 한 번 실행하면 됩니다. 사용자가 삭제한 바로 가기는 다시 만들지 않습니다.

0.2.128 교직원 PC 자동 실행
- 클라이언트를 처음 실행하면 현재 Windows 사용자의 시작프로그램 폴더에 바로 가기를 등록합니다. 다음 Windows 로그인 때 띵동 로그인 화면이 열립니다.
- 자동 실행은 Windows 설정 → 앱 → 시작에서 끌 수 있습니다. 프로그램을 옮겼다면 새 위치에서 한 번 실행하세요.

0.2.127 로그인 비밀번호
- 관리자와 교직원은 8자 이상으로 비밀번호를 설정할 수 있습니다. 교직원 일괄 등록 시에는 8자의 무작위 임시 비밀번호가 발급됩니다.
- 서버와 클라이언트를 모두 업데이트하면 첫 로그인과 비밀번호 재발급에도 같은 기준이 적용됩니다.

0.2.126 공용 설정 저장과 누적 기록
- 환경 설정 → 교직원 정보 → 반별 담임 보기에서 반별 배정을 확인하세요. 서버가 변경을 거절하면 이유가 표시됩니다.
- 서버 관리의 Windows 로그인 시 자동 실행 표시가 서버 실행 파일과 시작 인수의 실제 등록 상태를 확인합니다.
- 메시지함은 100개씩 더 볼 수 있고, 검색은 전체 보관 기록을 대상으로 합니다.
- 새 PC에서 첫 로그인 시 개인 기록 보호 키가 디스크에 저장될 때까지 기다립니다.

0.2.125 메시지 상태 표시
- 보낸 메시지에서 발송 대기, 상대 PC 저장 완료, 읽음, 회신 또는 제출 완료를 구분해 확인하세요.
- 회신·제출 요청의 ‘수신자별 현황’에 저장, 읽음, 업무 응답이 각각 표시됩니다.
- 요청 목록에서 완료를 표시해도 메시지 원문을 열기 전까지 읽음 알림이 발생하지 않습니다.

0.2.124 PC 교체 시 기록 옮기기
- 기존 PC의 환경 설정 → 내 메시지 보관·보안 → 내보내기에서 .dingdong 파일을 저장한 뒤 띵동을 종료하세요.
- 새 PC에서 같은 학교 계정으로 로그인을 시도하고 ‘기존 PC 보관 파일 가져오기’로 복사한 파일을 선택하세요.
- 새 파일에는 메시지, 첨부와 개인 암호화 키가 들어 있습니다. 비밀번호 없이 열 수 있으므로 본인만 접근할 수 있는 곳에 보관하세요.
- 이전 버전의 보관 파일을 가져올 때는 원래 비밀번호를 입력하세요.

0.2.123 송수신 안정성 및 대용량 첨부
- 문제가 있는 수신 메시지는 분리하고 정상 메시지는 계속 받습니다.
- 환경 설정 → 내 메시지 보관·보안에서 수신 문제를 다시 확인할 수 있습니다.
- 설치형 첨부: 파일당 500 MB, 메시지당 합계 2 GB, 본문 이미지 포함 최대 20개.
- 파일은 분할 전송하고 연결이 끊기면 이어서 보냅니다. 서버에서는 실제 발송 후 10일 뒤 삭제합니다.
- 대용량 파일도 개인 암호화 보관 파일에 포함하며, 백업 저장 실패 시 이전 백업을 유지합니다.
- 서버와 클라이언트를 함께 업데이트하세요. 화면 체험은 파일당 2 MB, 합계 3 MB로 유지됩니다.

0.2.122 이름 변경 및 후속 보완
- 화면·문서·실행 파일·내부 코드 이름을 띵동 / Dingdong으로 변경했습니다.
- 기존 PC 기록·서버 계정·인증서·이전 보관 파일은 계속 사용할 수 있습니다.
- 첨부는 본문 이미지 포함 최대 20개, 각각 2 MB, 합계 3 MB입니다.
- 동시 로그인/보안 조회의 키 중복 생성을 방지했습니다.
- 자동 실행 시 클라이언트/서버 역할을 유지합니다.
- 이름 호환: resources/app/BRANDING.md
- 배포 파일 생성: resources/app/DEPLOYMENT.md


0.2.121 송수신 오류·백업 복원·상태 표시 보완
- 거절된 발송을 분리하여 다른 송수신을 계속하고 보낸함에서 다시 보낼 수 있습니다.
- 오래된 백업의 발송 대기는 자동 재전송하지 않습니다. 기존 기록을 유지하면서 복원합니다.
- PC 저장 완료·읽음·회신/제출 완료를 구분합니다.
- START-CLIENT.cmd: 실제 클라이언트
- START-SERVER.cmd: 교내 서버
- 기존 START-DEMO.cmd는 화면 체험 모드입니다.
- 정책, PC 이전과 검증 안내: resources/app/privacy/README.ko.md
- 서버와 각 PC의 클라이언트를 모두 이 버전으로 업데이트한 뒤 재시작하세요.
- 메시지 및 읽음·회신 알림은 상대 PC의 저장 확인 후 서버에서 삭제합니다.
- 기존 메시지·수신자·대화방 기록도 각 PC의 이전 확인이 끝나면 제거합니다.
- 첨부 파일은 암호화하지 않고 실제 발송 후 10일이 지나면 삭제합니다.
