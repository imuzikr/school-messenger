# 메시지 내용 암호화 성능 시험

이 디렉터리는 성능 비교 전용입니다. 실제 앱의 암호화 기능을 구현하거나 활성화하지 않습니다.
`crypto-cost.cjs`의 조합은 연산 비용을 재기 위한 시험 모델이며, 제품에 사용할 암호화 프로토콜이 아닙니다.

## 실행

저장소 루트에서 Node 24 이상으로 실행합니다.

```powershell
node resources/app/benchmarks/message-crypto/run.cjs --smoke=true --output=.artifacts/message-crypto-benchmark/smoke.json
node resources/app/benchmarks/message-crypto/run.cjs --repeats=30 --warmups=5 --output=.artifacts/message-crypto-benchmark/results.json
```

실제 `server/index.cjs`를 별도 프로세스에서 수정 없이 실행합니다. 서버는 `127.0.0.1`의 임의 포트에만 바인딩합니다.
OS 임시 폴더에 독립 SQLite 데이터베이스와 합성 사용자/세션을 만들고, 종료 시 해당 임시 폴더만 지웁니다.
실제 사용자 데이터, 실행 중인 데모, 교내 서버에 접근하지 않습니다. 사용자/세션 생성, 키 생성, TLS 연결 준비는 측정 전에 끝냅니다.

## 비교 조건

- 단체 발송의 '70건'은 **한 메시지를 수신자 70명에게 한 번에 발송**하는 것으로 해석합니다.
- 개인 1명/단체 70명 × 본문 약 1 KiB/10 KiB/50 KiB의 조합을 측정합니다.
- 별도로 70명 × 10 KiB 본문 + **암호화하지 않은 1 MiB 첨부파일**도 측정합니다.
- 일반 메시지와 암호화 메시지 모두 HTTPS를 사용합니다. 비암호화는 '메시지 내용의 추가 암호화 없음'이라는 의미입니다.
- 암호화 대상은 제목/본문/HTML이며, 별도 첨부파일의 바이트와 파일명은 암호화하지 않습니다.
- 내용은 메시지당 한 번 AES-256-GCM으로 암호화하고, 새 내용 키를 수신자 및 발신자에게 X25519/HKDF-SHA256/AES-GCM으로 각각 감쌉니다. Ed25519 서명과 수신 검증도 포함합니다.
- 공개키는 시험 시작 전에 생성해 서로 신뢰하도록 설정합니다. 실제 사용자 인증·키 검증·키 교체·복구 정책을 구현하지 않습니다.
- 기존 서버 API를 그대로 사용하기 위해 암호문과 **모든 수신자의 감싼 키 목록**을 `body`에 넣습니다. 실제 제품에서는 수신자에게 필요한 키만 전송하는 형식으로 최적화할 수 있습니다. 이 시험 포맷은 보수적인 비용 모델입니다.
- 각 쌍에서 동일 본문과 동일 첨부파일을 보내며, 매 회차 이전 시험 메시지를 제거해 이력 크기를 동일하게 유지합니다.
- 측정 순서는 평문→암호문, 암호문→평문을 번갈아 사용합니다. 준비 측정은 제외하고 이상치는 임의로 제거하지 않습니다.
- 일반 메시지는 준비 5쌍 + 본 측정 30쌍, 첨부파일은 준비 5쌍 + 본 측정 12쌍입니다.

## 실제로 측정하는 경로

발신자 암호화 → HTTPS `/sync` → 서버 SQLite 저장 → SSE 알림 → 수신자 HTTPS `/bootstrap` → JSON 파싱 → 서명 검증/복호화 → 원문 일치 확인.

발신자가 전송 후 자신의 목록을 다시 받는 `/bootstrap` 요청도 동시에 수행합니다.
`allMessagesMs`는 **마지막 수신자가 메시지를 검증하고 복호화할 때까지**의 시간입니다.
첨부파일 시험에서는 모든 수신자가 `/attachment`로 파일을 받고 SHA-256으로 동일성을 확인하며, 그 종료 시점은 별도 `allAttachmentsMs`입니다.
첨부파일 다운로드는 모든 수신자가 본문을 확인한 뒤 동시에 시작합니다. 요청 순서에 따라 먼저 시작한 파일 다운로드가 다른 사람의 본문 수신을 지연시키는 효과를 분리하기 위한 조건입니다.

`encryptMs`는 발신 준비 비용, `decryptPerRecipientMs`는 한 수신자의 복호화/일치 검사 비용입니다.
별도 마이크로벤치마크는 HTTP와 DB를 제외한 암복호화 비용을 측정합니다.
`wireBytes`는 요청/응답 JSON 본문의 바이트 합계이며 HTTP 헤더, TLS, SSE 프레임을 제외합니다.
CPU와 메모리는 이 PC에서 실행되는 서버 프로세스 및 **70개 수신자를 모두 모의한 클라이언트 프로세스 전체**의 값입니다.
이벤트 루프 지연도 이 시험용 Node 프로세스의 값이며 실제 앱 화면 멈춤 측정값이 아닙니다.

## 결과를 해석할 때의 한계

- **한 PC의 루프백 통신**입니다. 학교 LAN, 서로 다른 성능의 70대 PC에서 재측정해야 합니다.
- 모든 수신자가 하나의 Node 프로세스에서 복호화하므로, 개별 수신자 지연을 70대 실제 PC의 지연으로 그대로 해석하면 안 됩니다.
- Electron IPC, 렌더링, 사용자 PC의 영구 저장/백업, 첫 로그인과 키 등록은 포함하지 않습니다.
- 실제 메시지 이력 누적, 의미 있는 날짜의 자동 일정 추출, 암호화된 데이터 검색은 시험하지 않습니다.
- 신뢰할 수 있는 키 배포, 키 교체, 래칫, 재전송 공격 방지 상태 저장, 복구, 보안 감사는 별도 구현·검증 대상입니다.
- 수신 확인 후 서버 본문 삭제 및 파일 10일 보관 기능도 구현하지 않습니다.
- 첨부파일은 서버에서도 읽을 수 있는 원본 데이터로 저장됩니다. 관리자에게 첨부 내용까지 숨기는 시험이 아닙니다.
- 캐시, GC, 백그라운드 부하 등으로 암호화 쪽 측정이 더 빠르게 나올 수 있습니다. 음수 차이를 암호화의 속도 개선으로 해석하지 않습니다.

원시 회차, 중앙값, 95백분위, 실행 환경은 결과 JSON에 함께 남습니다.
암복호화 성공 및 변조/잘못된 키 거부 검사, 모든 수신자의 원문 일치, 첨부파일 원본 일치 확인이 실패하면 시험은 실패합니다.

## 결과 보고서와 문자열 처리 대조 시험

```powershell
node resources/app/benchmarks/message-crypto/encoding-control.cjs
node resources/app/benchmarks/message-crypto/report.cjs .artifacts/message-crypto-benchmark/results.json
```

`encoding-control.cjs`는 첨부파일이 본문과 같은 JSON TEXT 레코드에 저장되는 현재 구조에서, 한글이 포함된 레코드와 ASCII 레코드의 읽기·파싱 비용을 비교합니다. 파일 포함 시험에서 암호화군이 오히려 빠른 결과가 나타난 원인을 분리하기 위한 보조 시험이며, 네트워크나 암호화 성능 시험 자체는 아닙니다.

`REPORT.ko.md`와 `summary.json`을 생성하며, 본 측정에 기록된 서버/클라이언트/시험 소스의 SHA-256이 현재 파일과 일치하는지도 확인합니다.
