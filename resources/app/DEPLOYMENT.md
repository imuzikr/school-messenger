# Windows 배포 파일 만들기

개발 폴더에 포함된 Electron 실행 파일과 현재 코드로 무설치 폴더와 ZIP을 만듭니다. 외부 전송이나 설치는 하지 않습니다. 빌드 PC에는 Node.js가 필요하며 사용 PC에는 필요하지 않습니다.

`resources/app`에서 실행합니다.

```text
npm run build:windows-client
npm run build:windows-server
npm run build:windows-demo
```

결과는 프로젝트의 `dist/Dingdong-역할-버전-시각` 폴더와 ZIP입니다. 기존 결과를 덮어쓰거나 삭제하지 않습니다. 실행 파일을 더블 클릭하면 해당 배포본의 역할로 시작합니다. `START-CLIENT.cmd`, `START-SERVER.cmd`, `START-DEMO.cmd`로 역할을 지정할 수도 있습니다.

프로그램과 필요한 라이브러리만 포함합니다. 테스트·성능 시험·개인 프로필·학교 서버 데이터·과거 작업 백업·검증 화면은 포함하지 않습니다. 코드 서명된 설치 프로그램을 만드는 기능은 아닙니다.

서버 설정에서 자동 실행을 켜면 서버 모드로 등록합니다. Windows 재부팅 후 자동 실행, 다른 PC의 접속, 학교 방화벽과 70대 실기기 부하는 별도로 확인해야 합니다. 기존 이름의 외부 바로가기는 새 실행 파일로 연결하세요.

교직원용 클라이언트를 처음 실행하면 현재 Windows 사용자의 시작프로그램 폴더에 바로 가기를 등록합니다. Windows에 로그인하면 띵동이 열립니다. 자동 실행을 끄려면 Windows 설정 → 앱 → 시작에서 띵동 항목을 끄세요. 바로 가기는 `Win + R` → `shell:startup`에서도 확인할 수 있습니다.

서버와 클라이언트가 모두 0.2.130 이상이면 로그인할 때 ‘이 PC에서 자동 로그인’을 선택할 수 있습니다. 임시 비밀번호를 변경하고 나면 다음 실행부터 같은 Windows 계정에서 메신저로 바로 들어갑니다. 학교 서버가 늦게 켜져도 클라이언트가 연결을 다시 시도합니다. 로그아웃하거나 비밀번호가 초기화되거나 약 90일간 사용하지 않으면 다시 로그인해야 합니다. 새 PC에서는 자동 로그인을 다시 선택하세요.

0.2.129부터는 바탕화면에서도 ‘띵동 메신저’ 바로 가기로 클라이언트를 열 수 있습니다. 바탕화면 바로 가기를 삭제해도 Windows 로그인 시 자동 실행 설정은 유지됩니다.

기존 이름과 기록 호환은 `BRANDING.md`, 보관 정책은 `privacy/README.ko.md`에 설명되어 있습니다.

0.2.123부터 대용량 분할 전송과 수신 오류 격리를 지원합니다. 서버·클라이언트를 함께 교체하고, 기존 사용자 데이터 폴더는 유지하세요. 서버 relay-files 폴더는 임시 첨부 저장소이며 설정·계정 백업이나 배포 ZIP에는 포함하지 않습니다. 개인 .dingdong 보관 파일에는 메시지·암호화 키·내려받은 첨부가 포함됩니다.

PC를 교체할 때는 0.2.124 이상 클라이언트의 환경 설정 → 내 메시지 보관·보안에서 파일을 내보낸 후 이전 PC의 띵동을 종료하세요. 새 PC에서 같은 학교 서버에 연결해 본인 계정으로 로그인을 시도한 뒤 ‘기존 PC 보관 파일 가져오기’에서 복사한 파일을 선택하세요. 새 형식은 별도 비밀번호가 없으므로 파일을 가진 사람이 내용을 읽을 수 있습니다. 이전 버전이 만든 파일은 원래 비밀번호로 가져옵니다.
