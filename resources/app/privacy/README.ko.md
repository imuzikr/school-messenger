# 메시지·메타데이터 암호화와 PC 보관 — 0.2.125

이 변경은 설치형 클라이언트와 교내 HTTPS 서버에 적용됩니다. `http://127.0.0.1:8765`의 브라우저 체험 화면은 로컬 예시 화면이며 실제 암호화 송수신 서버가 아닙니다.

## 실행과 사용

- 프로젝트 루트의 `START-SERVER.cmd`: 실제 교내 서버 관리 앱.
- 프로젝트 루트의 `START-CLIENT.cmd`: 실제 설치형 클라이언트. 서버 관리 앱에서 내보낸 연결 파일을 가져온 뒤 로그인합니다.
- 기존 `START-DEMO.cmd`: 화면 체험 모드를 유지합니다.
- 환경 설정 → **내 메시지 보관·보안**: 개인 보관 파일 내보내기/가져오기, 내 보안 번호와 상대방 번호 대조.
- 로그인 화면의 **기존 PC 보관 파일 가져오기**: 새 PC에서 계정 로그인을 시도한 뒤 기존 키와 기록을 가져올 때 사용합니다.

모든 사용자는 처음 한 번 로그인해 공개키를 등록해야 합니다. 이후에는 수신자가 접속하지 않은 동안에도 암호문을 서버에서 대기시킬 수 있습니다. 키 미등록 수신자에게는 평문으로 대신 보내지 않고 오류를 표시합니다.

## 확정된 보관 정책

| 데이터 | 서버 | 사용자 PC |
|---|---|---|
| 메시지 제목·본문·서식, 대화·인용문 | 암호문으로 임시 보관, 전원 수신 완료 후 삭제 | 보낸 사람은 전송 전에, 받는 사람은 수신 시 영구 저장 |
| 회신·제출의 응답 메모 | 암호문으로 임시 보관, 발신자에게 전달 후 삭제 | 응답자와 원 요청 발신자의 PC에 보관 |
| 일반 첨부파일·본문 이미지 | 파일 내용 암호화 없이 10일간 제공 | 발신 파일 및 내려받은 파일을 보관 |
| 예약 메시지의 첨부파일 | 실제 발송되는 시점부터 10일, 예약 회수 시 미발송 파일 제거 | 발신 파일 및 내려받은 파일을 보관 |
| 수신 대상·송수신 시각·파일명·대화방 정보 | 메시지와 함께 암호화해 전달, 마지막 대상 PC의 저장 확인 후 삭제 | 보낸함·받은함·대화 기록에 보관 |
| 수신 완료·읽음·회신/제출 상태 | 별도 암호화 알림으로 대기, 상대 PC 저장 확인 후 삭제 | 각 PC의 수신자별 현황에 반영 |
| 폴더·중요 표시·담임 업무 이월/삭제·개인 읽음 위치 | 서버로 보내지 않음 | 이 PC에만 저장 |
| 메시지에 연결한 일정·수업 안내 | 암호화 메시지로 전달, 일정 변경도 별도 알림으로 전달 | 참여자의 PC에 보관 |
| 본문에서 자동 추출한 개인 일정·메모 | 새로 생성한 내용은 서버로 보내지 않음 | 이 PC에서 추출·검색·편집 |

**수신 완료는 읽음과 다릅니다.** SQLite의 `synchronous=FULL` 트랜잭션으로 PC 저장과 재시도할 수신 확인을 먼저 확정한 다음 서버에 확인을 보냅니다. 저장 실패·복호화 실패·서명 검증 실패 시에는 수신 확인을 보내지 않습니다. 서버 본문 삭제 후에도 수신자별 읽음/완료 상태는 따로 변경할 수 있습니다.

파일은 로그인과 무작위 접근 증표 확인을 거쳐 내려받습니다. 파일명·메시지 ID와 연결한 영구 권한 목록은 서버에 남기지 않습니다. 파일의 접근 증표는 암호화 메시지 안에서 수신자에게 전달하며, 서버 파일에는 증표의 해시만 보관합니다. 파일 저장소에는 무작위 ID, 내용, 만료 시각, 접근 증표 해시가 남습니다. 업로드 중에는 임시 발신자 정보도 사용하지만 발송 수락 시 제거합니다. 만료 시점부터 다운로드를 차단하고 주기 작업으로 파일 데이터를 삭제합니다. 이미 내려받은 PC 파일은 유지합니다. 서버가 꺼져 있었다면 재시작 후 만료 파일을 정리합니다. 예약은 실제 발송 시점부터 10일을 계산합니다.

수신되지 않은 메시지와 알림에는 임의 만료를 적용하지 않았습니다. 장기 미접속자가 있으면 그 PC에 전달할 암호문과 최소 라우팅 정보가 계속 대기합니다. 발신자가 오프라인일 때 읽음 알림도 서버에서 대기하며, 나중에 발신자 PC가 저장을 확인하면 삭제됩니다. 사람이 알림 창을 클릭할 때까지 서버에서 기다리는 방식은 아닙니다.

전달 대기 중에는 서버가 발신 계정·대상 계정·임시 전송 ID·예약 시각·첨부의 무작위 ID를 알아야 합니다. 각 대상자의 저장 확인으로 해당 대기 행을 지우며, 마지막 확인으로 암호문과 전송 행을 함께 제거합니다. 계정·조직도·공개키·로그인 세션·학교 공용 업무/일과표 및 메시지와 무관한 공유 일정은 서비스 운영 데이터로 남습니다. 중복 재전송 방지를 위해 계정별 마지막 전송 순번 하나도 유지합니다. 이 숫자에는 과거 메시지 ID·수신자·시각을 저장하지 않습니다. 0.2.131부터 서버는 접수 응답이 끊긴 경우에 대비해 발신 계정과 암호문 해시에서 계산한 일회성 확인값을 잠시 보관합니다. 발신 PC가 접수를 기록해 확인하면 삭제하며, 확인이 오지 않아도 24시간 후 만료됩니다. 서버 백업에서는 제외합니다. 순번이 겹치고 같은 전송임을 증명할 수 없으면 PC에 ‘발송 여부 확인 필요’로 남기고 자동 재발송하지 않습니다.

## 암호화와 키

- `jose` 6.2.14의 표준 JWE/JWS 구현 사용. 앞선 성능 시험의 자체 암호화 모델은 사용하지 않습니다.
- 본문: AES-256-GCM. 단체 메시지는 공통 암호문 하나와 수신자별 ECDH-ES+A256KW 키 정보를 사용합니다.
- 발신자 서명: Ed25519. 메시지 식별자·발신자·대상자·대화방을 서명 및 인증 데이터에 포함합니다.
- 암호화 키는 클라이언트에서 생성합니다. 서버에는 공개키만 등록하며, 관리자가 개인키를 내려받거나 비밀번호 초기화로 교체하는 API는 없습니다.
- Windows 설치형 앱의 개인키와 PC 기록은 Electron `safeStorage`로 Windows 사용자 계정에 묶어 보관합니다. 안전한 OS 저장소가 없으면 평문 저장으로 대체하지 않습니다. 첨부파일은 전송 시 본문 암호화에 포함하지 않으며, PC 보관 DB에는 OS 보호를 적용합니다.
- 0.2.124부터 PC 이전 파일(.dingdong)은 비밀번호 없이 내보내고 가져옵니다. 파일에 메시지·개인키·첨부를 여는 키가 함께 들어 있어 복사본을 가진 사람이 내용을 읽을 수 있습니다. 내보낸 파일은 본인만 접근할 수 있는 곳에 보관하세요. 띵동은 가져올 때 같은 학교 서버와 계정의 등록 키, 기록 목록의 서명, 각 첨부의 무결성을 확인합니다. 기록 목록의 한도는 256 MB이며 대용량 첨부는 나누어 처리합니다. 이전 비밀번호 형식(.dingdong 또는 .ieum)을 선택하면 그때 설정한 비밀번호를 묻습니다.

처음 받은 공개키를 PC에 고정하고 변경 시 송수신을 중단합니다(최초 사용 시 신뢰). **서버가 최초 공개키 배포부터 악의적으로 조작하는 상황까지 방어하려면 상대방과 별도 경로로 보안 번호를 대조해야 합니다.** 관리자가 파일 저장소에서 암호문만 읽는 경우와 공개키 배포 자체를 공격하는 경우는 다릅니다.

이 버전은 **한 계정의 주 사용 PC 하나**를 전제로 합니다. PC 교체 시 기존 PC에서 보관 파일을 내보내고 새 PC로 가져온 뒤 이전 앱을 종료합니다. 여러 PC가 동시에 수신하는 기기별 동기화나 Double Ratchet에 의한 전방향 안전성은 구현하지 않았습니다. 개인키와 보관 파일을 모두 잃으면 서버에서 삭제한 메시지를 복구할 수 없습니다. PC 자체가 침해된 상황까지 방어하지는 않습니다. 독립적인 보안 감사를 거친 제품이라는 의미도 아닙니다.

## 재시도와 백업

0.2.121부터 서버가 명확히 거절한 발송은 개별 실패 기록으로 분리합니다. 해당 항목 때문에 다른 발송이나 수신을 멈추지 않습니다. 보낸함에서 실패 사유를 확인하고 **다시 보내기**를 누르면 새 전송 식별자로 재시도합니다. 일시적인 연결/서버 오류는 원래 전송 식별자와 순번을 유지한 채 대기하며, 수신은 별도로 계속 시도합니다. 서버가 수락했는지 불명확한 전송을 건너뛰어 뒤의 순번을 먼저 보내지는 않습니다.

PC 보관 파일을 가져올 때 현재 PC의 최신 기록·읽음·폴더 설정은 보존하고 없는 기록을 추가합니다. 대화방은 기존 메시지를 유지하면서 빠진 메시지를 합칩니다. 백업의 메시지 발송·업무 응답·공용 변경 명령은 자동 재실행하지 않습니다. 과거에 이미 전달된 발송 대기일 수 있기 때문입니다. 보낸함의 **발송 여부 확인 필요 → 내용 확인 후 새로 작성**, 받은 요청의 **응답 수정**에서 확인 후 다시 처리합니다. 저장·읽음 확인은 이미 PC에 기록된 사실이므로 새 전송 식별자로 복구할 수 있습니다. 파일 검증이나 PC 저장에 실패하면 가져온 기록 전체를 되돌립니다. 자동 정기 백업은 이번 변경에 포함하지 않습니다.

화면의 **발송 대기**는 아직 서버로 전달되지 않은 PC 대기, **상대 PC 저장 대기**는 상대의 저장 확인을 기다리는 상태, **PC 저장 완료**는 상대 PC 저장 확인을 받은 상태, **읽음**은 상대가 메시지를 연 상태입니다. 회신·제출 완료는 별도 업무 응답입니다. 읽음 알림에도 ‘읽었습니다’라고 표시합니다.

발신 내용·메타데이터·전달 대기를 PC에 먼저 저장합니다. 받는 PC는 내용, 현황, 중복 확인 기록, 후속 알림과 서버에 보낼 저장 확인을 하나의 FULL 트랜잭션으로 확정합니다. 서버가 수락한 직후 연결이 끊기거나 저장 확인 응답이 유실되어도 재시도합니다. 삭제된 전송을 다시 생성하지 않도록 서명한 계정별 순번을 확인합니다. 이미 로그인한 앱은 연결이 끊겨도 보관된 기록을 표시하고 알려진 상대에게 보낼 내용을 대기시킬 수 있습니다. 앱을 새로 실행한 후 로그인에는 서버 연결이 필요합니다.

서버의 **설정·계정 백업**은 임시 메시지·알림·전달 메타데이터·첨부파일·개인 항목·기존 메시지 및 대화방 목록을 제외합니다. 따라서 이 백업으로 미배달 메시지를 복원할 수 없습니다. 메시지 기록 복원은 각 PC의 개인 보관 파일로 해야 합니다. 서버 삭제 때 `secure_delete`와 WAL 체크포인트를 적용하지만, 관리자가 별도로 만든 디스크 이미지나 기존 외부 백업을 원격으로 지울 수는 없습니다.

회수는 미전달 메시지를 서버 대기열에서 제거하고, 이미 저장한 상대 PC에는 별도 회수 요청을 보냅니다. 상대 앱은 아직 열지 않은 메시지를 숨기고 결과를 돌려보냅니다. 읽었거나 별도 저장한 사본까지 강제로 삭제하는 기능은 아닙니다.

## 기존 버전 기록의 이전

서버와 모든 클라이언트를 함께 업데이트해야 합니다. 구형 메시지 변경 API는 기본 운영 모드에서 차단합니다. 기존 메시지·대화방·읽음·회신·담임 업무 기록은 각 계정의 PC로 이전하고, 보낸 사람과 대상자의 저장 확인이 모두 끝난 뒤 기존 서버 행과 연결된 개인 일정 정보를 제거합니다. 한 명이 접속하지 않거나 PC 저장에 실패하면 해당 기록은 이전 대기로 남습니다. 파일은 기존 만료 시각을 보존한 별도 접근 증표로 이전합니다. **이전 대기 중인 기존 평문에는 종단간 암호화 보호가 소급 적용되지 않습니다.** 기존 외부 백업도 자동 삭제하지 않습니다. 이전 PC에서 이미 받은 본문을 새 PC가 가지고 있지 않다면 보관 파일을 가져와야 이전을 완료할 수 있습니다.

원래 서버 파일에 있던 첨부파일은 원래 발송 시각을 기준으로 보관 기간을 계산합니다. 업그레이드 시점부터 새로 10일을 연장하지 않습니다.

## 0.2.123 추가 검증과 첨부 정책

설치형 파일 첨부는 파일당 500 MiB(화면 표기 500 MB), 한 메시지 합계 2 GiB(화면 표기 2 GB), 본문 이미지 포함 20개까지입니다. 본문에 직접 넣는 이미지는 각각 2 MB, 합계 3 MB로 유지하며 큰 이미지는 파일로 첨부합니다. 브라우저 화면 체험은 기존 2 MB/3 MB 제한을 유지합니다.

파일 준비·전송·다운로드는 1 MiB 조각으로 처리합니다. 발신 파일과 내려받은 파일은 계정별 PC 파일 저장소에 보관하고 SQLite에는 파일 정보만 저장합니다. 서버는 원본 바이트를 별도 파일로 저장하며 파일 내용을 암호화하지 않습니다. 파일 이름은 암호화 메시지에만 포함됩니다. 서버에는 무작위 파일 ID, 크기, SHA-256, MIME 형식, 완료 여부, 만료 시각, 접근 증표 해시가 남습니다. 전송 준비 중 발신 계정·임시 만료 시각은 전송 수락 시 지웁니다. 완료되지 않은 업로드는 마지막 조각 이후 24시간 임시 보관합니다.

서버가 파일을 모두 저장하고 원본 해시를 확인한 뒤 메시지를 전달합니다. 파일 전송 중에도 일반 메시지를 받을 수 있습니다. 끊긴 업로드·다운로드는 이미 저장된 위치에서 계속하며, 앱이나 서버를 재시작해도 이어받습니다. 예약 첨부는 실제 발송 시점부터 10일이고, 그전에 회수하면 제거합니다. 다운로드 완료 사본은 서버 만료 후에도 PC에 남습니다.

수신 시 검증할 수 없는 메시지는 PC에 오류 식별 정보만 따로 기록하고 서버에 저장 확인을 보내지 않습니다. 정상 메시지는 다음 페이지까지 계속 처리합니다. 상태 표시와 내 메시지 보관·보안 화면에서 수신 확인 필요 건수를 확인하고 다시 시도할 수 있습니다. PC 디스크 쓰기 실패는 수신 성공으로 처리하지 않습니다. 페이지 위치는 단조 증가하는 번호를 쓰며 전달 행 삭제 후에는 메시지 식별자 없는 숫자만 남습니다.

추가 시험: 손상된 105개 수신 항목 뒤 정상 수신, 강제 프로세스 종료 직후 복구, 서버 재시작, 분할 전송 응답 유실, 중복 없는 재전송, 파일 원본 일치, 실제 500 MiB 파일과 합계 2 GiB 전송, 첨부 포함 암호화 백업의 손상·저장 실패 처리. 실제 크기 시험은 node tests/large-files.cjs, 설치형 화면 시험은 DINGDONG_TEST_LARGE_FILE=1 환경에서 node tests/privacy-native.cjs로 실행합니다. 학교 PC 실기기 연결·방화벽·재부팅 자동 실행 시험은 별도입니다.
